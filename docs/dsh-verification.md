# DSH compatibility and minimal integration

Inspected official [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) master, reported revision `4b399c39a6d1479cd84ca591b4d7c88e24d38a96` (2026-11-22), package release `0.2.3-alpha.2`. Compiled and integration-tested with the published packages at that exact release, Cordis `4.2.0-alpha.1`, Node `24.22.3`.

| Capability | Verified source and implementation decision |
| --- | --- |
| Plugin entry / DI | Named exports `name`, `inject`, `apply(ctx, config)`; inject only `tools` and `systemPrompt`. See [lifecycle](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/docs/user/develop/framework/index.md). |
| Tools | `ctx.tools.register(defineTool(...))`, official schema DSL, canonical output schema/render, cooperative signal. Only one new tool, `taste_memory`. [Real contracts](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/core/tools/src/contracts.ts). |
| Search/fetch | Native `web_search` / `web_fetch` are supplied by `@deepseek-ai/dsh-tool-web` over `ctx.web`. No wrappers or independent search service. Actual route/provider credentials determine availability; the plugin never assumes their presence. |
| Prompt / dynamic context | `ctx.systemPrompt.section()` for stable instructions, `.context()` for user-data snapshots; `interpolate: false` prevents user content being interpreted as variables. The documented async `system-prompt/assemble` waterfall reloads disk before each assembly; synchronous provider reads use the latest loaded snapshot. |
| Native memory | No general `ctx.memory`, Memory Section Provider or model-facing Memory Tool was found in this release's packages/docs. Credential-test “memory providers” are in-memory credential fixtures, not durable taste storage. This machine had no installed `dsh` command or discoverable default DSH configuration at inspection time. Therefore JSON fallback is used, rather than pretending to integrate a nonexistent API. A future memory backend needs fresh source verification; no speculative adapter is shipped. |
| Human provenance | Tool execution reads `exec.agent.session.deriveMessages()` and accepts fact quotations only from the latest message with `role=user` and `source.kind=user`; injected user-role context is ineligible. Confirmation/rejection additionally requires the full human `/taste ...` command. |
| Cleanup | Official registries own fiber-scoped effects. Actual Cordis unload tests verify that tool, prompt section and context disappear; disk memory intentionally survives plugin removal. |
| Distribution | Current bundle uses `dsh.bundle.patch`; `cordis.patch.yml` inserts the package row. Compiled `lib/` is committed and checked in CI, so Git installs need no arbitrary prepare script. [Official packaging guide](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/docs/user/develop/basic/publish.md). |

Only one local person may use a profile/memory file. Scope the plugin to a dedicated gaming profile. The plugin does not install a runtime, choose a model, enable broad permissions, create agents, override existing web providers, or claim end-to-end model tests without actual credentials. Recommendation quality and research budgets are model instructions, not a deterministic ranking engine or a runtime quota.
